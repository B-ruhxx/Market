2 · PROPUESTA DE SOLUCIÓN

Nuestra propuesta en la nube

Arquitectura elástica, segura y asistida por IA en Google Cloud Platform

La solución implementada

  • Qué: Plataforma web e-commerce con Asistente Virtual Inteligente (Gemini AI).
  • Proveedor: Google Cloud Platform (GCP).
  • Región: us-central1 (Iowa), alta disponibilidad de cuotas Compute, SQL y Gemini.
  • Modelo: Híbrido IaaS + PaaS gestionado (Compute Engine + Cloud SQL PostgreSQL 16 + Cloud Storage).
  • Servicios: Compute Engine · Cloud SQL · Cloud Storage · Cloud NAT · Gemini API.

¿Por qué la nube?

  • Cero hardware local: Sin riesgo de apagones, hardware defectuoso o cuellos de botella físicos.
  • Escalabilidad elástica: Capacidad de duplicar instancias en segundos ante tráfico intenso.
  • Pago por uso: Aprovisionamiento exacto mediante Infraestructura como Código (Terraform).
  • Foco en el negocio: Google opera la resiliencia de la base de datos; el equipo se enfoca en la tienda y la IA.
Antes → Después: Servidor local saturado sin IA y con caídas en campañas → Plataforma Cloud 24/7 con HTTPS, base de datos privada en VPC Peering y Asistente Gemini integrado.

Seguridad, disponibilidad y costo

Alineamiento con normativas de protección y estimación presupuestal mensual

Seguridad (Ley N.° 29733)

Service Account con permisos mínimos (roles/storage.objectAdmin), Cloud SQL en red 100% privada sin IP pública, SSL mandatorio (sslmode=require), certificados TLS automáticos y Actuator bloqueado externamente.

Disponibilidad (SLA 99.9%)

Infraestructura en Google Cloud con hardware redundante y políticas restart: unless-stopped. Posibilidad de activar Alta Disponibilidad regional en Cloud SQL ante contingencias.

Escalabilidad Horizontal

Escala de 1 a N réplicas del contenedor Spring Boot en segundos vía Docker Compose y balanceo Nginx, desacoplando sesiones en Redis.

3 · DESPLIEGUE

Problemas y cómo los resolvimos

Incidentes reales encontrados durante la implementación y su mitigación técnica

Problema Causa Raíz Solución Aplicada
Error en Terraform por APIs inactivas El proyecto GCP nuevo no tenía habilitadas por defecto las APIs de Cloud SQL y Service Networking. Se ejecutó gcloud services enable para SQL Admin, IAM y Service Networking previo al apply.
Fallo de autenticación admin tras reinicio La variable DEMO_SEED_ENABLED=true omitía la inicialización idempotente de usuarios de prueba. Se ajustó DEMO_SEED_ENABLED=false en .env garantizando la creación persistente de credenciales.
Error 503 / Cuota en Gemini API Saturación temporal en llamadas concurrentes al endpoint principal del modelo generativo. Se implementó fallback automático al modelo gemini-3.1-flash-lite con reintentos limpios y manejo de errores.
Conexión rechazada a Cloud SQL Aislamiento de red privada sin acceso público y exigencia de certificados seguros. Se enrutó mediante VPC Peering interno (10.98.0.3) con parámetro JDBC sslmode=require.
Lección aprendida: La infraestructura como código y la estricta gestión de variables de entorno (.env) eliminan discrepancias y permiten replicar entornos en minutos.

5 · CONCLUSIONES

Conclusiones y recomendaciones

Evaluación técnica integral del proyecto y hoja de ruta arquitectónica

1. Propuesta: La arquitectura basada en Google Cloud (Compute Engine + Cloud SQL + GCS + Gemini AI) resolvió eficazmente la saturación por tráfico estacional y dotó a la tienda de capacidades inteligentes por menos de US$ 50 al mes.
2. Despliegue: La infraestructura como código (Terraform) y la orquestación en Docker Compose garantizaron un despliegue 100% reproducible, sin exponer la base de datos a internet y con cifrado TLS 1.3 automático.
3. Demostración: Las cuatro pruebas en vivo validaron latencias de respuesta < 400 ms, escalabilidad horizontal elástica, alta disponibilidad ante fallos y estricta seguridad perimetral.

Recomendaciones para Producción a Gran Escala

(1) Migrar la carga de trabajo a Google Kubernetes Engine (GKE) o Cloud Run para auto-escalado horizontal automático basado en métricas de CPU/solicitudes; (2) Activar Google Cloud Armor como WAF contra ataques DDoS e incorporar Cloud CDN para acelerar la entrega de catálogo e imágenes en el edge.
